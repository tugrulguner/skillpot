## Prepared release notes

### Nineteen skills, two new workflows

The collection grows from seventeen skills / 113 bundle files in v0.5.0 to nineteen skills / 133 bundle files. The additions are:

- **invariant-audit 0.1.0** — inspect one named guarantee against bounded source and observations, separating its intended invariant, enforcement, independent expectations, observed counterexamples and unresolved limits. Produce the seven-section `invariant-audit.md`; this is not formal proof or permission to modify enforcement. Optional input-only practice includes inert source, not expected answers. See the [first-use guide](../invariant-audit-first-use.md) and [accepted worked example](../../examples/invariant-audit/README.md).
- **performance-investigation 0.1.0** — investigate one measured symptom through competing mechanisms and discriminating checks. Produce the seven-section `investigation.md` with the narrowest supported diagnosis or unresolved cause and a permission-aware handoff. Distinguish source inspection from timing profiles, declared artifacts from verified runtime bytes, and endpoint observations from continuous behavior. Inspection is default; diagnostic execution requires explicit bounded authorization. The optional projection-path contrast is hypothetical, not a shipped toggle or performed ablation. See the [first-use guide](../performance-investigation-first-use.md) and [accepted worked example](../../examples/performance-investigation/README.md).

The seventeen existing workflows and their bytes remain unchanged from v0.5.0: benchmark-audit, bug-repro, change-impact, claim-check, decision-brief, dexpot, document-actions, experiment-design, incident-triage, intpot-cli, intpot-python, refpot-database, repository-readiness, summonpot, summonpot-code-review, summonpot-pr-review and verification-loop. Collection publication does not change individual skill versions, upstream product prerequisites or maturity. Refpot preview and repository-readiness experimental boundaries remain in force.

### Setup, discovery and evidence boundaries

The interval also includes the completed v0.5.0 stable-default alignment: setup/first-use commands and website discovery distinguish published instructions from separately pinned current-source additions; historical release inventories, receipts and evaluation records keep their original scope. Catalogue/homepage/agent-map entries, responsive discovery tests, first-use guides and separately pinned distribution records were added for the two new workflows. These changes are part of the release interval, not new changes to the seventeen existing instruction bundles.

The worked packets and finite fixture tests are authored review material, not agent task trials. The performance packet retains published summary receipts and inert candidate source with its full MIT notice; original raw client streams, histograms and wheel bytes remain unavailable. It establishes neither a repeatable regression nor its cause. Installation evidence concerns filesystem placement, complete resources, hashes, locks, selection and removal, not native loading, automatic selection, safety, task efficacy or universal correctness. A collection release grants no authority to execute targets, install dependencies, access production/credentials, optimize, publish, spend or merge.
