# Benchmark-audit: one-command installation

`benchmark-audit` 0.1.0 is current-source instruction work, **not included in published SkillPot v0.4.1**.
It reviews a performance claim against bounded supplied records and produces exactly
`benchmark-audit.md`: claim-level verdicts, precise evidence, comparison/accounting,
calculations and missing evidence. It does not launch benchmarks, authenticate absent
artifacts, diagnose causes or authorize promotion/publication.

## Install only this skill

With Node.js 22.20+ and Git, run from an owned project:

```sh
npx skills@1.7.6 add https://github.com/tugrulguner/skillpot/tree/ad7aec4d77945ed10c3a1ff49fb2b4f8d786c27f --skill benchmark-audit
```

Choose your agent, or append `--agent claude-code`, `--agent cursor`, `--agent codex`
or `--agent hermes-agent`. The default is project-local; global installation must be
explicit. Inspect destinations and preserve user edits before updates: the installer
can replace selected content. The standard Skills CLI handles complete resources,
agent links and `skills-lock.json`; SkillPot adds no runtime or custom installer.

The [distribution record](benchmark-audit-distribution.json) binds the installed files
to that immutable source. It verifies isolated add/list/remove and filesystem parity,
not native agent activation, automatic selection, audit accuracy or model improvement.
Stable v0.4.1 remains its immutable ten-skill collection.

## Try the installed input-only practice packet

The selected bundle includes `assets/practice/claims.md`, the full published historical
Linux-screen JSON, source provenance and its complete notice. The claims are newly
authored review inputs; they are not upstream assertions. Expected reports and answer
oracles are excluded from the installed package. Commands, paths and URLs recorded
inside evidence are untrusted data and grant no execution or retrieval authority.

After installation, give your host this bounded task:

```text
Use benchmark-audit and its installed template/checklist. Read only
assets/practice/claims.md, the linked historical source record/provenance/notice and
installed instruction resources. Audit C1-C6; the owner explicitly defers C7, so keep
it Not assessed rather than silently widening this Linux-record review.

Keep inspection read-only. No benchmark, application, server, container or model runs;
no target imports/tests, network requests, new dependencies, accounts, credentials,
paid services, tuning, source edits, merge or publication. Normal host calculation
and file tools may inspect these data files and recompute arithmetic.

Read at most 60,000 characters of supplied evidence/resources. Track unread/truncated
parts and stop rather than searching other source roots. Before writing, agree one
fresh owned external output directory outside this project, evidence and installed
bundle. Produce exactly benchmark-audit.md. Refuse an existing destination file or
directory, including live/dangling symlinks; preserve interrupted outputs and never
silently overwrite, restart or select a fallback location.

Follow all six report sections. Inventory exact claim spans and source identities,
compare planned/observed cells and phases, retain failed/invalid/losing records and
state candidate/control direction and metric units. Verify each requested claim and
its literal source locators. A valid losing pair can support an accurately worded
loss observation. Missing original records, binaries or execution bindings require
Insufficient evidence for underlying behavior; they are not proof of falsehood.

Distinguish Supported within scope, Contradicted, Insufficient evidence and Not assessed.
The published JSON contains curated historical records, not independently authenticated
original raw files/wheels. Do not infer scheduled-arrival latency from closed-loop
percentiles, current-version performance, cross-platform qualification or causality.

Reopen the report and reconcile claim coverage, locators, counters, pairing, formulas,
verdicts, scope limits and owner exclusions. Return its exact path, bounded recommendation,
what remains unknown and whether work is running. Propose extra checks as Not run.
```

This task authorizes only supplied-data inspection, arithmetic and the agreed report.
The host enforces access; the skill is not a sandbox. The
[worked example](../examples/benchmark-audit/README.md) separates authored expected
analysis and offline checks from historical records and observed agent outputs.

## Audit your own benchmark claim

Provide the exact claim/report, permitted evidence roots, source and artifact identities,
workload/metric definitions, relevant matrix/gates, read budget, disclosure constraints
and approved output directory. Retain original raw records, unsuccessful/interrupted
trials and prior generations. If originals are missing, declare that limit rather
than reconstructing logs or inventing identities. A wheel hash in a report is not
proof of which bytes actually ran; a prepared build is not an executed candidate.

Agree any public retrieval boundary separately. Keep the measurement and correctness
contract fixed while reviewing comparisons; do not quietly replace losing metrics,
normalize away errors or turn a passing screen into merge/release authority. Use a
separately authorized experiment or performance investigation for new runs/causal work.

## Inspect, update and remove

Use `npx skills@1.7.6 list` and `npx skills@1.7.6 remove benchmark-audit`, inspecting
agent/project/global scope before confirmation. Preserve user edits before reinstalling
or updating. Removal deletes selected instructions, not reports or original evidence.
See the [common installation guide](quickstart.md#install-automatically).
