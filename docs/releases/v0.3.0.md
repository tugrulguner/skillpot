# v0.3.0 release preparation

**Status: proposed, not published.** The latest published collection remains v0.2.0.
This document does not authorize a merge, tag, deployment, release or user-installation
change. The source baseline is
[`6861f96488ffa8bf7ca66919734c8d5196a041da`](https://github.com/tugrulguner/skillpot/commit/6861f96488ffa8bf7ca66919734c8d5196a041da),
including the reviewed four-guide refresh. Select the final approved preparation
merge commit as the release candidate after review; do not publish this branch.

## Proposed release notes

### Four refreshed project skills

This collection refreshes four consumer instruction bundles while retaining eight
skills overall: seven public project/contributor packages and the experimental
repository-readiness workflow. It adds no agent runtime, installer or marketplace.

- **Intpot CLI and Python, skill versions 0.3.0:** updated pinned guides describe
  bounded binding-chain explanations, exact body-reference locations and source
  digests. The guides also document a newer, explicitly unreleased numeric-range
  conversion slice; do not attribute that guarantee to Intpot v0.16.0.
- **Summonpot consumer, skill version 0.2.0:** updated guidance covers
  application-authenticated context, version-specific producer-choice execution,
  and the explicitly unreleased multiple-choice extension. Authentication and
  operation authorization remain application-owned; prefix effects are not rolled
  back by later failures.
- **Dexpot consumer, skill version 0.2.0:** the pinned v0.8.0 guide adds synchronous
  process-scoped lifecycle resources, bounded shutdown and deferred-cleanup limits.
  Do not assume enter/exit thread affinity or cleanup after forced termination.

The Summonpot contributor guides, Refpot preview and repository-readiness workflow
are unchanged. Complete MIT notices remain preserved; upstream guides are unchanged
byte-for-byte snapshots behind adapted portable entry points.

### Documentation and repository improvements since v0.2.0

The source distribution now includes the product-owned
[documentation website](https://skillpot.modepot.io/), canonical generated guides and
Markdown downloads, native theme/search/navigation, clearer selective-copy setup
and troubleshooting, and explicit current-source versus published-release labels.
The website is independently deployed; including its source does not make it a
runtime requirement for a skill.

Repository maintenance now includes Python 3.11–3.14 checks, lint/type checks,
browser verification, a fail-closed aggregate CI gate, scoped contribution forms,
weekly dependency proposals and a guard against unsupported standalone TypeScript
major upgrades. Required checks and production restrictions are repository controls,
not permissions or safety guarantees conferred by installed instructions.

### Install or upgrade after publication

**The following v0.3.0 command is for use only after the tag and public archive exist.**
Before then, retain the working v0.2.0 install in the main quickstart. Downloading a
candidate does not register skills with a host or install underlying products.

From a new source location you own:

```sh
git clone --branch v0.3.0 --depth 1 https://github.com/tugrulguner/skillpot.git skillpot-v030
cd skillpot-v030
git rev-parse HEAD
```

Compare the resolved commit with the published release identity. This clone already
selects v0.3.0: do not then run the older v0.2.0 checkout from the tagged quickstart's
source-selection section. Continue with its [host placement instructions](../quickstart.md#3-place-it-where-your-agent-discovers-project-skills),
copying the entire chosen directory into a new destination. For example:

```sh
# Replace with an actual existing project you own.
SKILL_ROOT=/absolute/owned-project/.claude/skills
(
  set -eu
  mkdir -p "$SKILL_ROOT"
  mkdir "$SKILL_ROOT/intpot-python"
  cp -R skills/intpot-python/. "$SKILL_ROOT/intpot-python/"
)
```

The plain `mkdir` refuses an existing destination, including a same-name symlink.
For an existing installation, inspect the old/new directory diff and preserve local
edits; do not treat this example as an overwrite or automated migration. The same
complete bundle works with the documented Claude Code, Cursor, Codex or other host
placement. For Hermes' existing URL installer, derive `REV` from this inspected
v0.3.0 checkout rather than a moving main or the old stable revision, and follow the
[normal scan/permission procedure](../project-skill-installation.md#hermes-direct-url-one-selected-skill).

### Verification and limits

Source/resource/hash/license checks and offline copy tests qualify the instruction
distribution surface. Website tests qualify their named build and browser behavior.
No new native host session, authentication probe, product execution, model call,
performance study or broad usefulness evaluation is part of this release preparation.
Historical examples and results retain their original source pins and assistance.
Installation grants no authority to install dependencies, expose listeners, change
application data, publish, push or merge. Refpot and repository-readiness keep their
preview/experimental boundaries.
