# Field-consistency follow-up protocol

These are four fresh fictional packets, authored after observation-001 to inspect the same field-consistency failure classes in different settings. They are targeted follow-ups, not held-out generalization samples, a controlled comparison, or a user study. Original observation-001 outputs must remain untouched.

One ordinary host-assisted attempt per case will receive the supplied complete candidate bundle, the task envelope and the input document only. No worker may read sibling cases, parent-only expectations, repository examples, development source or earlier outputs. The host may require supplementary skills; do not disable safety or mandatory loading to create apparent isolation. Audit actual loaded guidance, failures and exact final artifacts before stating results.

Candidate source identity and copied package hashes will be frozen before dispatch after implementation review. Input/task and expectation hashes below are frozen before any worker execution. No baseline condition is planned; results cannot establish an effect caused by the instruction edits or broader reliability. Do not silently revise failed outputs or use targeted retries as fresh success.

Only two new output files per case are allowed: brief.md/evidence.md or actions.md/questions.md. No network, credentials, installs, external messages, purchases, implementation, profile edits or unrelated project writes. Raw runner logs remain private; share only independently inspected source packets and generated artifacts.
