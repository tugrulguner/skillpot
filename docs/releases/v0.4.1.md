# v0.4.1 release preparation

**Not published.** v0.4.1 is a proposed patch collection release. Published v0.4.0
and all stable installation defaults remain unchanged until separate publication
approval and public tag/archive verification. This document creates no tag or release.

The reviewed implementation baseline is main commit
`e3ba0893f2ae03587206c4ee8d15c5187c29ebea`, the merged field-consistency correction.
The final preparation head/tree and local archive identities belong in the candidate
verification record and preparation pull request. The eventual release must select
its separately approved merged main commit, not a moving branch or unmerged head.

## Prepared release notes

### Corrections to two workflows, still ten skills

v0.4.1 distributes the same ten skills as v0.4.0. It is a patch because inputs,
output filenames, permissions, prerequisites and resource paths remain compatible.
This is an instruction snapshot, not a runtime or product-package upgrade.

- **decision-brief, instruction version 0.1.1:** keep the decision owner, intended
  reader and purchasing/approval authority distinct throughout the brief. Register
  supported role, constraint and preference claims in the evidence ledger. Verify
  precise source sentence/clause locators and distinguish actual completion timing
  from when completion is reported or confirmed. Unknown actual timing cannot become
  a failed gate merely because confirmation arrives later.
- **document-actions, instruction version 0.1.2:** absent completion reporting remains
  Unknown rather than an asserted Incomplete status. Retain explicitly reported
  statuses and known approval roles even when an individual is unnamed. A proposer or
  approver does not automatically become an assignee.

The other eight bundles retain their v0.4.0 bytes: intpot-cli, intpot-python,
summonpot, dexpot, refpot-database, summonpot-pr-review, summonpot-code-review and
repository-readiness. Refpot retains its preview boundaries; repository-readiness
remains experimental. The seven-package upstream catalogue and immutable pins are
not refreshed by this patch.

### Select and install only after publication

**Run the following source-selection command only after the tag and public archives exist.**
Until then, stable setup remains v0.4.0, or use an explicitly inspected source revision.
From a fresh source location you own, choose one complete bundle and one trusted
project-local skill root. Claude Code placement below is one host example:

```sh
PROJECT="/absolute/owned-project"
SKILL="decision-brief"
SKILL_ROOT="$PROJECT/.claude/skills"
(
  set -eu
  : "${PROJECT:?Choose an existing owned project}"
  : "${SKILL:?Choose one exact catalogue name}"
  : "${SKILL_ROOT:?Choose a trusted project-local skill root}"
  test -d "$PROJECT"
  git clone --branch v0.4.1 --depth 1 https://github.com/tugrulguner/skillpot.git skillpot-v041
  cd skillpot-v041
  # Copy the complete selected bundle.
  test -f "skills/$SKILL/SKILL.md"
  mkdir -p "$SKILL_ROOT"
  mkdir "$SKILL_ROOT/$SKILL"
  cp -R "skills/$SKILL/." "$SKILL_ROOT/$SKILL/"
)
```

Compare the selected checkout's HEAD with the independently verified release identity
before using the copied instructions. The exclusive mkdir refuses existing files,
directories and same-name live or dangling symlinks. Preserve local edits and use a
fresh destination; do not merge over an existing installation. A failed copy may leave
an incomplete new directory, which must be preserved and inspected rather than deleted
or retried over automatically. Trusted parent paths and host permissions remain your
responsibility; this is not a sandbox. No global skill store is changed by this recipe.

The outer fail-closed block prevents copying from a decoy current directory after a
clone failure. Local preparation tests exercise the literal copy fragment separately
from source selection; the nonexistent future tag is not represented as a successful
public clone.

**Do not rerun** the v0.4.0 clone or detached-checkout selections retained in the tagged
quickstart, because they would select the older instructions. Keep this v0.4.1 checkout
when using the quickstart's packet preparation and task prompts. The tag may retain
prepublication metadata labels; once publication is verified, those labels describe
the preparation snapshot rather than excluding the listed corrections. Reconcile
current-source defaults/status only in a separate postpublication change.

For other hosts use the existing [harness-neutral placement guide](../quickstart.md#3-place-it-where-your-agent-discovers-project-skills).
For Hermes' selective URL installer derive the revision from the inspected v0.4.1
checkout and follow its normal scanning/permission process, not the old stable pin.
No native client or account probe is needed to inspect the archive or copy a bundle.
