# Compatibility and verification boundaries

Version `0.1.1` is included in published SkillPot v0.4.0 at
`3624eaaf2aa6c870e1dad6190ac3466e4e378f35`. Publication does not extend the
verification scope below or relabel assisted observations as isolated task evidence.

Use with a host that can read supplied text, inspect file destinations, create two
new files in an owned approved directory and reopen them. No particular model, native
client, account, network, paid service or dependency installation is needed. Existing
host format/placement guidance applies; instruction compatibility is not a tested
native-activation claim. The procedure is not a sandbox.

The workflow supports supplied readable notes, briefs and specifications. Binary,
scanned or recorded material requires separately available and permitted extraction
tools; this bundle provides no parser/OCR/transcription integration. Input extraction
errors and unreadable portions must be disclosed. The initial version deliberately
preserves deadline expressions with no date normalization.

## Verification scope

Offline source-contract/resource checks, authored example checks, copy/refusal tests
and website navigation checks can validate their stated structural and file/UI scope.
The repository example is authored expected material, not an agent-generated result.
Native activation, semantic accuracy on arbitrary documents, completeness of extracted
obligations, cross-host reliability and improved task performance are not established.
No live client/model evaluation is required or claimed for this instruction bundle.

When recording optional task observations, retain original inputs/outputs and audit
which other guidance the host actually loaded. Supplementary extraction skills or
inherited instructions limit attribution; do not describe mixed-guidance attempts as
isolated tests of this package or weaken host policies to manufacture isolation.
Test a hostile source with fresh permitted outputs separately from collision refusal:
a collision-first stop before reading that source supplies no injection-resistance evidence.

Assignment, acceptance, status and external authority remain distinct even when all
sources are readable. The owner reviews the resulting artifacts; the workflow does
not perform, publish, schedule or accept extracted work. Interrupted outputs and
pre-existing files require explicit recovery permission, not automatic cleanup.
