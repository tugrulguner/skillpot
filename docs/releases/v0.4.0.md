# v0.4.0 release preparation

**Not published.** v0.4.0 is a proposed collection release. Published v0.3.0 and its
stable installation defaults remain unchanged until separate publication approval
and tag/archive verification. This document creates no tag or release.

The reviewed implementation baseline is main commit
`2b8040fece04dc159a44e72e909e376f5d0583a3`. The preparation change adds this record,
source-copy regressions and a roadmap link; it does not refresh any skill bundle.

## Prepared release notes

### Two new workflows, ten skills

v0.4.0 is proposed to distribute ten skills, adding two original workflows to the
eight in v0.3.0. This is an instruction collection, not a runtime, installer, registry
or product-package upgrade.

- **`decision-brief`, instruction version 0.1.0:** compare alternatives against a
  bounded evidence packet and create a proposed recommendation or deferral with an
  evidence ledger. Separate source facts, assumptions and missing information. The
  skill does not accept or implement the decision.
- **`document-actions`, instruction version 0.1.1:** extract source-stated work into
  actions.md and questions.md. Keep assignments separate from acceptance, proposals
  separate from commitments, deadlines verbatim and conflicting claims explicit.
  The latest corrections retain known historical owners, give status-conflicted
  items one unresolved record, and keep every supported requirement in its own
  canonical record rather than only in questions or coverage notes. A linked review
  checklist and source-item map reinforce those checks. Refuse existing output files
  or symlinks and request a fresh approved location. No tickets, messages or extracted
  work are performed.

The other eight bundles are retained unchanged from v0.3.0:

- `intpot-cli` and `intpot-python`, instruction versions 0.3.0.
- `summonpot` and `dexpot`, instruction versions 0.2.0.
- `summonpot-pr-review` and `summonpot-code-review`, instruction versions 0.1.0.
- `refpot-database`, instruction version 0.1.0, with its pinned preview boundaries.
- `repository-readiness`, instruction version 0.1.0, still experimental.

Instruction versions, collection versions and upstream product versions are distinct.
A collection tag does not promote a preview or experimentally scoped workflow.

### Examples, setup and evidence

Both new workflows include complete resources, authored worked examples and offline
checks. Decision-brief also includes its original three bounded task observations,
with their tested source identity and limitations. Source-only first-use guides now
cover complete bundle copying, bounded inputs, fresh outputs and practical prompts.

The document-actions worked example is fictional reference material, not an observed
agent extraction. Separate task follow-ups were assisted and loaded supplementary
host guidance; they do not establish isolated skill efficacy, general extraction
accuracy, comparative improvement, repeatability or cross-harness reliability. The
private task traces and local observation packages are not release contents.

Since v0.3.0, current-source discovery and website guides also distinguish both new
workflows from the eight-skill published collection. The website deploys independently;
its source is included without becoming a runtime dependency of an installed skill.
Historical examples, notices and observations remain at their original identities.

### Install or upgrade after publication

**Run the following v0.4.0 source-selection command only after the tag and public archives exist.**
Until then, use the current published v0.3.0 instructions or explicitly inspected source.
Downloading a candidate does not register skills with a host or install product dependencies.

From a fresh source location you own:

```sh
git clone --branch v0.4.0 --depth 1 https://github.com/tugrulguner/skillpot.git skillpot-v040 &&
cd skillpot-v040
```

Compare `git rev-parse HEAD` with the published release identity before using it.
The clone already selects v0.4.0. **Do not rerun** the v0.3.0 clone or any older
source-only detached-checkout commands retained in the tagged quickstart: they would
change the selected snapshot. Prepublication labels such as "source-only" or
"unreleased" in retained package/setup prose describe the preparation snapshot;
a published v0.4.0 tag includes both bundles listed above. A separately authorized
post-publication update reconciles current-source defaults/status; it does not move the tag.

Choose one complete directory from the catalogue. This example selects document-actions;
change SKILL to decision-brief or another exact catalogue name when choosing a different
workflow. Replace PROJECT with an existing project you own and use one trusted
project-local skill root from your host's documented placement:

```sh
PROJECT=/absolute/owned-project
SKILL=document-actions
SKILL_ROOT="$PROJECT/.claude/skills"
(
  set -eu
  : "${PROJECT:?Choose an existing owned project}"
  : "${SKILL:?Choose one exact catalogue name}"
  : "${SKILL_ROOT:?Choose a trusted project-local skill root}"
  test -d "$PROJECT"
  test -f "skills/$SKILL/SKILL.md"
  mkdir -p "$SKILL_ROOT"
  mkdir "$SKILL_ROOT/$SKILL"
  cp -R "skills/$SKILL/." "$SKILL_ROOT/$SKILL/"
)
```

The exclusive mkdir refuses existing files, directories and same-name live or dangling
symlinks. Preserve local edits and choose a fresh destination rather than copying over
an old installation. A later copy failure can leave a partial new directory: inspect
and preserve it instead of automatically deleting or rerunning over it. Trusted parent
paths remain your responsibility; this is not a sandbox. Other skill directories and
global stores are not updated by this recipe.

Claude Code project scope is one example. Use the existing
[host placement instructions](../quickstart.md#3-place-it-where-your-agent-discovers-project-skills)
for Cursor, Codex or another supported host. For Hermes' existing selective URL installer,
derive the source revision from this inspected checkout and follow its normal scanning
and permission process, not an older stable pin. No native client or authentication
probe is required to inspect or copy the source. Follow the new workflows' task/input
preparation and prompt sections while staying in this selected v0.4.0 checkout and
skipping their older source-selection commands.

### Verification and authority limits

Offline source, resource, metadata and notice checks qualify their distribution scope.
Authored examples are not empirical performance evidence. No additional model session,
authentication probe, product execution or comparative study is part of preparing this
release. Existing assisted task records keep their original source identities, failures
and qualifications.

Instructions confer no authority to install dependencies, access accounts or credentials,
change application data, execute extracted work, publish, push, merge or bypass host
approval. Upstream product prerequisites and pinned unreleased-feature warnings remain
in force. Refpot and repository-readiness retain their preview/experimental boundaries.
